# Mode: release notes or changelog

For telling users what changed in a product.

## Shape

- Group the changes as **New**, **Improved** and **Fixed**, or use the person's own grouping.
- Each item is one or two sentences, written from the user's side: what they can now do, or what no longer goes wrong. Don't describe what the team did internally.
- Lead with the change people will notice most.
- Name things exactly as they appear in the product.
- No marketing adjectives. "You can now export to PDF" beats "Introducing powerful new export capabilities".

## Draft layout

```markdown
## <Version or date>

**New**
- ...

**Improved**
- ...

**Fixed**
- ...

Gaps: <every [ADD: ...]>
```
