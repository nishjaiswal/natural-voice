# Engineering terms

| When they say something like | Term |
|---|---|
| the part people see | front end / client |
| the part on the server | back end |
| how the app talks to the server | API |
| where the data is kept | database / data store |
| it keeps working without internet | offline support |
| it syncs between devices | sync |
| keeping a copy so it loads faster | caching |
| it got slow when lots of people used it | didn't scale / performance under load |
| it fell over | outage / incident |
| we put it out | shipped / deployed / released |
| we can undo the release | rollback |
| tests that run automatically | automated tests / CI |
| the old code nobody wants to touch | legacy code / tech debt |
| we rebuilt it without changing what it does | refactor |
| two things fighting over the same data | race condition |
| only some people can see it | access control / permissions |
| logging in | authentication |
| what you're allowed to do once logged in | authorisation |
| a program that runs on a schedule | scheduled job / cron job |
| plugging into another company's service | integration / third-party API |
